## Maintenance rule

Every new/changed field or feature requires a manual entry, meaningful test coverage, and an updated inventory in the same change. Keep history append-only. Expand the inventory as the app grows; do not delete references to evade failures. Screenshot reference changes require visual review. Structural validation cannot decide whether prose is correct; review that against actual behavior.

## Existing coverage to preserve

The earlier suites cover wizard membership, optional tasks, mixed estimate units, weekend and sprint overrides, dependencies and completed work, template application, commitment refresh and failures, backups/undo, generated/exported text, tablet/desktop layouts, and timeline scroll/grouping. New maintenance suites add leave editing, generated capacity invariants, real SQLite reopening/legacy data, visual references, accessibility, WebKit flows, larger data, and built-app smoke checks.

## Explicit blocked feature status (2026-10-12)
